# News permissions

`https://labulubius.com/news` uses the existing Supabase sign-in and `site_is_admin()` role. Requests to same-origin `/api/news` on Vercel relay over the existing Cloudflare Tunnel to the `web` host. Only the web host accesses FreshRSS at `127.0.0.1:8080` and its Docker PostgreSQL database; credentials stay in the root-readable `/etc/labulubius/news.env` EnvironmentFile of `labulubius-web.service`. The browser never receives API secrets. New direct feed subscriptions are represented inside FreshRSS by signed `drive.labulubius.com/api/news/feed/...` proxy URLs. The proxy pins a verified public address, revalidates every redirect, rejects private/special-use networks, and caps responses at 5 MiB. Configure a stable random `NEWS_FEED_PROXY_SECRET` (at least 32 characters) and optional `NEWS_FEED_PROXY_ORIGIN`; rotating the secret requires re-subscribing proxied feeds.

The public, read-only `/api/news?view=sidebar` exposes category names, subscription titles and the site owner's selected checkboxes to non-admin visitors; it does not expose feed IDs/URLs. `/api/news?view=publicArticles` serves the owner's selected, non-expired articles without authentication. Sidebar metadata is cached for 30 seconds on the web host, but selection is read from disk per request. Visitors can read articles and follow their original links; checkboxes and management controls remain disabled. When there is exactly one preference file it defines the owner; with multiple preference files set `NEWS_PUBLIC_OWNER_ID` on the web host to avoid selecting another admin's preferences. Admin-only News API views and all writes still require admin authentication.

The admin News sidebar supports creating/renaming/deleting FreshRSS categories and adding/editing/deleting subscriptions. Deleting a category **unsubscribes all feeds in it, including hidden feeds, and removes their articles**; unchecking a feed merely hides it from News. Empty categories are created through FreshRSS's own PHP DAO in the local `freshrss` container. Input is validated and only admin-authorized server requests can reach these functions. The source-selection JSON files live outside the checkout at `${NEWS_DATA_DIR:-~/.local/share/labulubius/news}/<user-id>.json` on the web host. Feed names/URLs and articles are owned by FreshRSS, not Supabase. Generated authenticated sources are served from the dedicated `feeds.labulubius.com` tunnel hostname; no additional Docker container is required.

## CAU authenticated notices

The `web` deployment exposes a tokenized RSS source at `https://feeds.labulubius.com/api/news/cau/<token>` for China Agricultural University notices visible to the configured school account. The adapter performs the university's CAS form login server-side, keeps its cookie session only in memory, retries one fresh login when the session expires, and reads the authenticated PIM list API. It publishes only the notice title, date, publishing unit, original login-required link, and a sanitized one-to-two-sentence summary. Attachments and full notice bodies are not copied.

The CAU username and password are encrypted host credentials at `/etc/credstore.encrypted/cau-username` and `/etc/credstore.encrypted/cau-password`. `labulubius-web.service` receives them through `LoadCredentialEncrypted=`; the application reads them from `$CREDENTIALS_DIRECTORY`. They must never be added to `.env.local`, Git, command arguments, logs, or FreshRSS. The feed token is an HMAC derived from `NEWS_FEED_PROXY_SECRET`, so rotating that secret requires updating the FreshRSS subscription URL.

A root-owned `labulubius-cau-news-refresh.timer` invokes the installed `scripts/cau-news-refresh.sh` equivalent every 30 minutes. Successful refreshes atomically replace `${NEWS_DATA_DIR:-~/.local/share/labulubius/news}/cau-feed.json`; failed refreshes serve the last successful cache while it contains retained items. Both the generated feed and cache discard notices older than five days. The normal FreshRSS retention job independently removes imported copies on the same schedule.

## CIEE public notices

The separate `信电学院通知公告` source adapts the public China Agricultural University College of Information and Electrical Engineering column at `https://ciee.cau.edu.cn/col/col50450/index.html`. Its RSS endpoint is `https://feeds.labulubius.com/api/news/ciee`, protected by HTTP Basic authentication whose password is a source-specific HMAC derived from `NEWS_FEED_PROXY_SECRET`. Keeping the credential out of the URL prevents FreshRSS request logs from recording it. The adapter accepts only HTTPS pages on `ciee.cau.edu.cn` from column `50450`, bounds redirects and response sizes, reads recent article metadata and body text, and publishes the title, publication time, original link, and a sanitized one-to-two-sentence summary. Scripts, images, download links, attachments, and full bodies are not copied. No school login or additional credential is used.

A root-owned `labulubius-ciee-news-refresh.timer` invokes the installed `scripts/ciee-news-refresh.sh` equivalent every 30 minutes. The tracked unit templates are under `deploy/systemd/`. Successful refreshes atomically replace `${NEWS_DATA_DIR:-~/.local/share/labulubius/news}/ciee-feed.json`; failures serve the last successful cache and log only a generic error, never the feed credential, fetched body, or article URL. The cache and generated RSS retain only notices published in the last five days. FreshRSS imports it as an independent source and its normal retention timer removes expired copies.

Install or update the host job with root-owned files, then run `systemctl daemon-reload && systemctl enable --now labulubius-ciee-news-refresh.timer`. Monitor it with `systemctl status labulubius-ciee-news-refresh.timer labulubius-ciee-news-refresh.service` and `journalctl -u labulubius-ciee-news-refresh.service`; the normal feed import remains on FreshRSS's configured refresh schedule.

## Five-day article lifecycle

The installed `scripts/news-retention-install.sql` schema records first receipt times for auditing and installs anti-reimport safeguards. An hourly root-owned systemd timer (`labulubius-news-retention.timer`) runs the installed `/usr/local/sbin/labulubius-news-retention` wrapper, which sends root-owned `/usr/local/share/labulubius/news-retention-cleanup.sql` into `freshrss-postgres` via `docker exec -i`. Entries whose **publication time** is more than five days old, including attached tags, are hard-deleted. Tombstone hashes of expired `(feed ID, GUID)` prevent re-import while the subscription exists; they disappear when it is deleted. Those hashes contain no article content, but persist for the lifetime of the subscription. A hash collision could reject a different item. No article database backups are scheduled: GitHub stores code, **not** the article database.

`/api/news` queries the retained FreshRSS entries by publication time, so articles from a newly added source are merged into All articles chronologically instead of being promoted by their newer database insertion IDs. It also excludes anything older than five days before the hourly physical deletion runs. Job failures should be monitored via `systemctl status labulubius-news-retention.service` and `journalctl -u labulubius-news-retention.service`. Both administrators and signed-out visitors can use chronological cursor pagination.

To replicate this installation on a fresh, **empty** FreshRSS database: verify schema and run `docker exec -i freshrss-postgres sh -c 'exec psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < scripts/news-retention-install.sql`. Install both `scripts/news-retention-cleanup.sql` and `scripts/news-retention-hourly.sh` as root-owned files to the paths above. Deploy root-owned systemd service/timer units and enable the timer. The installer deliberately refuses nonempty entries without receipt timestamps; receipt metadata is not reconstructed from publication or `lastSeen`. Rerunning on an already installed DB is supported. If the FreshRSS database is recreated later, reinstall schema **before** fetching any articles.

## Verification

- Logged out, `/api/news?view=sidebar` shows the owner's checked state and `/api/news?view=publicArticles` shows selected articles in descending publication order, never older than five days. Follow the public continuation and verify there are no overlaps or ordering gaps. `/api/news?view=feeds` and `?view=articles` still return 401. Admin-only actions are rejected.
- Signed in as admin: add an RSS feed in Settings → RSS Sources, create tags in Settings → Tags, assign multiple tags to the source, then create a Watchboard requiring all those tags. Confirm its matching source count and articles; existing FreshRSS categories and subscriptions must remain intact.
- `/news` only fetches News data from `labulubius.com/api/news`; the tunnel host is only contacted server-to-server.
- Confirm `labulubius-news-retention.timer` is active, and check hourly run status. There should be no automatic article database backup; if backups are added later, their article contents need their own five-day lifecycle policy.

## Watchboards API (MVP)

Admin-only `GET /api/news/watchboards` returns `{tags:[{id,name}],watchboards:[{id,name,tagIds}],sourceTags:{[feedId]:tagIds}}`. Source IDs are available from the existing admin-only `GET /api/news?view=feeds`. Stale source assignments are hidden on read. Existing public `/news` reads are unchanged. Vercel relays this endpoint to web using the same Bearer authentication as the existing News API.

Admin-only `POST /api/news/watchboards` takes a JSON action and returns the updated state: `createTag` (name), `renameTag` (id,name), `deleteTag` (id), `setSourceTags` (feedId,tagIds), `createWatchboard` (name,tagIds), `updateWatchboard` (id,name?,tagIds?), or `deleteWatchboard` (id). Tag and board IDs are server-generated UUIDs. Names are nonempty, max 80 characters, unique case-insensitively per collection; tag IDs and source IDs must exist. Maximum 100 tags and boards each. Empty tag arrays match no sources; a board matches only sources carrying every selected tag (intersection/AND). Deleting a tag removes assignments and board references, but does not unsubscribe feeds.

Admin-only `GET /api/news?view=articles&board=<board-id>` reads retained articles from that board's tagged feeds, using existing cursor pagination. `feed` and `board` cannot be combined. Board filtering never changes the owner's source selection or the existing public News view.

Per-admin metadata is stored only on web at `${NEWS_DATA_DIR:-~/.local/share/labulubius/news}/<user-id>.watchboards.json` with private atomic writes, outside Git and separate from the existing selection files. Preserve this directory on future updates. Writes are serialized per user within the server process.
