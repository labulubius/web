# Forums

`/forums` aggregates public Discourse topic lists. Forum categories, origins and the shared source selection are managed by the site administrator in the sidebar; visitors can browse the selected sources and filter by category. The initial directory preserves the original OpenAI Community, Python Discussions and Discourse Meta sources. Changes are stored atomically in `~/.local/share/labulubius/forums/directory.json` on the web server (override with `FORUMS_DATA_DIR`). Back up this directory alongside other persistent data. A missing file uses the initial directory; deleting all sources/categories via the UI persists an empty directory.

The same-origin `/api/forums` endpoint serves the directory publicly and accepts authenticated administrator-only mutations (Supabase `site_is_admin()`); Vercel relays requests over the existing `drive.labulubius.com` tunnel. No Supabase schema migration is needed. Only public HTTPS origins without paths or custom ports can be configured; on every upstream connection the resolved public IP is pinned and redirects are not followed. Only Discourse `/latest.json`, `/t/<id>.json` and `/t/<id>/posts.json` endpoints are requested. OpenAI keeps its existing `?status=open` setting. Other forum platforms require a separate adapter. Responses are cached in each server process for five minutes, no posts are persisted, and the topic list shows only the first page of each source. Source errors do not prevent other sources from loading. Discussion replies are displayed as escaped plain text in batches of 20.

Manual checks: as administrator add/rename/delete a category, add/edit/delete a Discourse source, toggle multiple sources, filter by category and reload; verify the public view reflects the selection but cannot modify it. Reject localhost/private IP, non-HTTPS, non-standard ports and redirecting origins. Open a discussion with over 20 posts, follow an original link, and verify unknown/deleted sources and invalid IDs return 404. Check both the web server and Vercel deployments.
