# Private Drive

`/drive` is the administrator-only file manager on the main site (`https://labulubius.com/drive`, deployed to Vercel). Its API and persistent files run on the `web` server at `https://drive.labulubius.com/api/drive` and `/api/drive/upload` through Cloudflare Tunnel. The Drive subdomain's page redirects to the main-site UI; its API does not. Drive storage is separate from Share storage and Supabase Storage.

Every API request checks the Supabase Bearer token and `site_is_admin()` role. CORS permits only `https://labulubius.com`; the files are not public. Set `DRIVE_DATA_DIR` in the `web` service's `.env.local` to an absolute, writable directory **outside** the repository (for example `/home/debian/drive-data`). Do not set it on Vercel: that deployment does not hold persistent Drive data. Back up this directory separately from Git and Supabase, and copy the complete directory with permissions when migrating servers.

The UI supports nested folders, file upload and download, and recursive deletion. Uploads use resumable sessions with 8 MiB chunks; unfinished sessions can be resumed by reselecting the same file, survive a service restart, count against the quota and expire after seven days when new sessions are created. The **total Drive quota** is 5 GiB, including pending uploads; new uploads also require their size plus 4 GiB of available disk space. There is no longer a 20 MB per-file cap: an individual upload can be as large as the remaining quota, subject to disk space. Empty files are rejected, and an existing name cannot be overwritten. There is no sharing, public access, rename, preview or online editing. Downloads are attachments with no-store headers; large downloads require a browser with streaming file-save support (otherwise the UI refuses files over 64 MiB).

Keep disk usage, backup restores and the tunnel endpoint under review. Do not put Drive files under `public/` or assume that rebuilding/redeploying the application backs them up.
